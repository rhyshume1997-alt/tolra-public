## Failure causes and isolation diagnostics

- Initial matrix workers used the default temporary-folder setting. A main rerun with a writable temporary folder reduced the reported failures from 280 to 33; the archive file alone reported 48/48 passing. The additional SliQ edge-case file also reported 36/36 passing in its detached checkout with a writable temporary folder. The initial raw matrix numbers must not be represented as product regressions or as passing tests.
- The corrected-temp main diagnostics reported the same four failed files both in the original checkout and a detached checkout: marketing-home (16 failures), offline-replay-after-revocation (8), session-ended (1), offline-sync-authority (8).
- Each of those four files then reported passing in isolation with the normal thread pool: 18/18, 14/14, 12/12 and 11/11 respectively. The marketing stack points to Next image rendering reading missing window.location.href; the offline assertions show shared session/listener state. This strongly indicates cross-file state in the sequential workaround; exact per-test isolation causes are not all proved.
- Processes ending with signal 9 have no established application cause here. Resource or host termination is suspected, not proven. Timed-out processes did not produce a clean Vitest final summary. Some branches did not report every file, including DOM environments; those are incomplete runs.
- A VM-thread full-run diagnostic also stalled after its first files. A Node 22.23.4 version check was available, but no clean Node 22 whole-suite result was established. CI on its supported runtime, fresh dependencies, writable temporary space and normal isolation is still required.
- Branch heads differ in inherited source and conditional tests, so expected totals differ. Skipped counts are existing conditional tests; builder2 did not add skips to Vitest. Optional Playwright skips are reported separately in jobs 8 and 14.
