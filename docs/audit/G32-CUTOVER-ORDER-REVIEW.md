## Controlling dependency order

**138 → 140 → 141 → 144 → 145 → 146 → 147**, verifying each phase, **then** the approved JNR wipe, **then** independently verify retained records, all Marpet state and numbering holds. A Saturday clearing sheet cannot put a real wipe ahead of that chain.

The explicit positions proposed here are: SliQ no-write dry run → separately authorised load → independent full reconciliation → retained-record/hold recheck → day-of delivery-note counter → independent counter verification → separately approved app deployment → staff smoke checks. This preserves the approved release/wipe/hold/counter dependencies. Rhys must adopt the import/deployment positions before operations; this draft grants no permission. Historical import runs while the DLN hold remains: 147 expressly exempts authorised same-company historical imports. A paused organisation cannot import. Staff access/writers need their separately approved freeze plan; do not confuse that with the numbering hold. Imports can affect numbering, so the final counter verification must follow the final import. No rollback/re-apply shortcut is authorised.
