# Operator rehearsal for the atomic costing save

This is a runnable plan, **not evidence that the SQL works**. No database commands
were executed when this plan was written. Use the dedicated disposable local
Supabase stack only. Never use a hosted project, production copy, tunnel or shared
development database. The proposal is identical in #184 and #190; use #190 plus
this test-plan branch. No migration number is assigned to the proposal.

Prerequisites: Docker with enough storage, Supabase CLI 2.40.7, Node/npm and psql.
In CI, the normal database suite verifies the disposable backend, installs a missing
proposal as a test fixture, runs all ten checks, then removes only that fixture.
It never replaces or removes a pre-existing proposal. Manual runs retain the
explicit acknowledgement and installation commands below.
Onboarding's VFS Docker image expansion exhausted the practical storage budget;
resolve that environment limitation first. Tests have no skip path: unavailable
services, missing proposal or failed safety guards must fail the run.

Run these commands from the repository root on the disposable machine. They
install the proposal **only when the operator runs them**. Save the exit status
and test output; do not treat collection or type checking as a database pass.

```bash
set -euo pipefail
cd /workspace/tolra-public
git switch codex/costing-sql-test-plan
npm ci
export SUPABASE_BIN=/workspace/.tools/supabase-2.40.7/supabase
export SUPABASE_INTERNAL_IMAGE_REGISTRY=ghcr.io
npm run test:backend
# The file is generated by the LOCAL backend script; contains local demo keys.
# Never substitute another env file or print its contents.
set -a
. ./.env.test.local
set +a
python3 - <<'PY'
import os
from urllib.parse import urlparse
for name in ('TEST_DATABASE_URL', 'TEST_SUPABASE_URL'):
    url = urlparse(os.environ[name])
    if url.hostname not in ('127.0.0.1', 'localhost', '::1'):
        raise SystemExit(f'{name} must be loopback')
if urlparse(os.environ['TEST_DATABASE_URL']).port != 54322:
    raise SystemExit('Expected disposable Supabase database port 54322')
PY

# Refuses a non-synthetic database or an existing function; install is atomic.
PGOPTIONS='-c tolra.costing_throwaway=yes' psql "$TEST_DATABASE_URL" -X \
  -v ON_ERROR_STOP=1 \
  -c BEGIN \
  -f tests/scripts/costing-atomic-install-check.sql \
  -f supabase/proposals/builder2_costing_settings_atomic.sql \
  -c COMMIT

# Ten tests, including two independently connected concurrent transactions.
COSTING_ATOMIC_THROWAWAY=yes npx vitest run -c vitest.db.config.ts \
  tests/db/costing-atomic-proposal.test.ts

# Remove just the proposal; prove the 143 tables remain.
PGOPTIONS='-c tolra.costing_throwaway=yes' psql "$TEST_DATABASE_URL" -X \
  -v ON_ERROR_STOP=1 -f tests/scripts/costing-atomic-rollback.sql
```

The test creates two synthetic companies, admin/office/workshop/viewer people,
and an elevated support session. It never replaces the authorization functions.
Admin and office must save material, machine and defaults together; workshop,
viewer and elevated support must fail with `42501` and leave rates unchanged.
Support's active admin session is asserted before its denial, so a broken support
fixture cannot accidentally pass the authorization test.

Passing the other company as `p_org`, or reusing its material or machine ID, must
fail with `42501` and preserve **both** companies' settings. A negative margin
causes a late defaults constraint error (`23514`), after material deletion/addition
and machine update; all earlier writes must roll back.

The concurrency case holds the first save's transaction open. It checks
`pg_stat_activity` to prove the second connection is waiting on the advisory lock,
then commits the winner. The loser must return `40001`. The final material,
machine and defaults must all equal the winning payload, with no mixed values.

Expected: **10 tests passed**, none skipped. Any failure blocks SQL approval;
retain the actual error and investigate instead of changing assertions. The test
removes its synthetic fixtures in `afterAll`, including on assertion failures.
If interrupted, discard the whole dedicated stack rather than using production
cleanup SQL.

If a test fails, `set -e` stops before rollback. Run the rollback command above
separately to remove the proposal, preserving the nonzero test result. To discard
the dedicated stack afterward (deletes its local containers and volumes):

```bash
SUPABASE_BIN=/workspace/.tools/supabase-2.40.7/supabase npm run test:backend:stop
```

The rollback removes only `save_costing_settings_atomic(uuid,jsonb,jsonb)`, not
143's tables, source migrations or customer data. In this rehearsal the preflight
guarantees no previous function was overwritten. This rollback is not a production
rollback procedure.
